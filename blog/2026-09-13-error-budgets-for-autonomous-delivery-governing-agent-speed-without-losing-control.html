    Error Budgets for Autonomous Delivery: Governing Agent Speed Without Losing Control

    Autonomy should be earned, not assumed. Learn how an error budget policy decides when an AI-DLC run may skip approval gates and when the guardrails come back automatically.

    Most teams decide how much to trust an agent by temperament. The cautious lead keeps every approval gate switched on forever and wonders why the factory is slower than doing the work by hand. The bold one turns them all off after a good week and finds out in production what the gates were for.

    Neither is measuring anything. Both are guessing — and the guess gets re-litigated every sprint, usually by the same two people.

    Why: The Method Names the Tension But Not the Number

    The AI-DLC method definition paper is unusually candid that this is a real trade-off. One of its stated principles is "minimise stages, maximise flow" — cut handoffs and transitions so work moves continuously, which is the whole promise of iterations measured in hours. A few lines later the same principle insists human validation stays critical so that AI-generated code "does not become rigid ('quick-cement') but stays adaptable for future iterations", describing those validation points as acting "like a loss function", pruning wasteful downstream effort before it happens.

    The paper resolves the tension with a phrase rather than a number: oversight should be "minimal but sufficient". Sufficient for what, judged how, is left to the practitioner — and that gap is where error budgets belong. SRE settled this argument for production changes a long time ago, and the mechanism transfers directly: an error budget is a quantity of failure you have agreed to tolerate, and the policy attached to it decides what the organisation may do while the budget is healthy or spent.

    What: Autonomy as a Governed Setting

    The dials already exist. An AI-DLC run declares a workflow profile that sets its stage route, artefact depth, test strategy and ceremony — from express at 10 of 33 stages with minimal tests, through feature at all 33, up to enterprise, which keeps the compliance, security and observability work "because the cost of an undocumented decision is higher than the cost of the additional ceremony". Inside Construction there is a second dial: after the first approved stage, a one-time ladder prompt asks whether the rest of the run is autonomous or gated, and the answer is recorded in state.

    What is usually missing is anything connecting those dials to evidence. So connect them. Take the factory SLIs — gate first-pass rate, sensor pass rate, rework ratio, escaped defects in the first 14 days after merge — give each a target and a 28-day budget, and write the policy as an operations manual rather than an aspiration.

    The thresholds are yours to tune. The point is that the decision now has an owner, a number and a trigger, so nobody has to win an argument to make the factory safer on a bad week.

    How: Alert on the Burn, Not the Breach

    A monthly budget report tells you about a problem three weeks after it started. Apply multi-window burn rate alerting to the factory SLOs exactly as you would to a service: a fast window for an acute regression, a slow window for the drift no single run would flag.

    The acute case is common. A provider updates a model, or someone edits a rule that ships in every prompt, and the sensor pass rate drops fifteen points within hours. A 14.4x burn rate over one hour catches that the same afternoon. Without it, you find out when a reviewer gets tired of rejecting things.

    Budgets govern the aggregate, so you still need a fast local stop. AI-DLC's halt-and-ask is the right pattern: when a unit's code generation fails, Construction stops immediately — even in autonomous mode — and offers retry, skip or abort. If one unit in a parallel batch fails, the healthy units finish and keep their artefacts, and only the failed one raises the question. That is a circuit breaker with a human as the fallback path, and it is what makes the autonomous setting defensible at all. Autonomy that cannot stop itself is not autonomy, it is an unattended loop.

    Why This Makes You Faster

    The objection lands immediately: bureaucracy with extra steps. It is the opposite, for the same reason error budgets make product teams faster in production. Without a budget, the only safe posture is permanent caution, because no evidence would ever justify relaxing — so every gate you add is forever. With a budget, caution is priced. A team that produces clean runs accumulates headroom and spends it on speed, and everyone can see why they were allowed to.

    Start with one SLI. Set a target from four weeks of data, and write two lines: above target, Construction may run autonomous; below it, gates come back. You will stop arguing about whether the agents can be trusted, because you will be able to look it up.
